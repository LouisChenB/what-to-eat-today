# 一桌家常

用两台手机商量家里吃什么。按荤菜、蔬菜点菜，随机搭配一荤一素，查看菜谱，把菜单分享码发到微信聊天。

## 在微信开发者工具中打开

1. 选择「小程序 → 导入项目」，目录选 `D:\Software\cook`。项目入口 `app.json` 位于根目录，AppID 为 `wx652c8cd8d158f7b7`。
2. 点击「编译」。无需安装 npm 依赖或配置服务器。仓库内置 16 张成品图和 8 张做法图。
3. 在项目根目录运行 `node --test`，验证餐次、点菜、保存、菜谱翻页与分享码导入。

## 双机体验

1. 在微信公众平台的《小程序用户隐私保护指引》中声明读取剪贴板，填写用途「识别用户复制的菜单分享码」。有开发权限的账号上传代码后，管理员将开发版设为体验版，并给两台手机使用的微信号开通体验权限。
2. 两台手机进入同一个体验版本，用手机 A 点菜和改名。在菜单页点「分享码 → 复制分享码」，把代码粘贴到 B 的微信聊天。
3. 手机 B 复制分享码后打开小程序。已同意隐私指引时，可在检测提示中点「查看菜单」。首次可从首页「导入菜单」点「从剪贴板查看」并按微信提示授权，也可以手动粘贴。核对菜单后保存，再导入相同的代码并保存，确认历史只有一份，B 原来的草稿仍可编辑。
4. A 修改草稿后生成新的分享码。用两个代码分别导入，核对各自生成时的内容。用 B 再发给 A，验证两个方向。

微信后台资料可用名称「一桌家常」、简称「一桌」。介绍为「家常点菜工具，支持随机搭配一荤一素、查看菜品做法，并通过分享码交换菜单。」[微信头像](assets/profile/avatar.png)

## 目录

| 路径 | 用途 |
| --- | --- |
| `pages/` | 点菜、菜单、历史 |
| `components/`、`templates/` | 共用菜品行与详情模板 |
| `data/`、`lib/` | 菜品、菜谱、餐次、分享、本机存储 |
| `assets/dishes/`、`assets/brand/` | 成品图、桌景、灰图 |
| `meat/`、`vegetables/` | 详情分包及做法图 |
| `assets/design/`、`assets/profile/` | 设计稿与微信头像 |

功能细节见 [SPEC.md](SPEC.md)，界面规则见 [design.md](design.md)。

## 素材来源

- 用户提供的成品照片包含可乐鸡翅、糖醋排骨、小炒黄牛肉、孜然羊肉、虾仁炒蛋、蚝油生菜、青椒炒蛋和洋葱炒鸡蛋。现有仓库保存供小程序使用的压缩副本。
- 两个详情分包内的 8 张做法图均来自用户素材，以 JPEG 保存。番茄炒蛋各步骤按两张图的原顺序展示。
- 做法图路径由菜谱数据在运行时生成。`project.config.json` 关闭上传时的无依赖文件过滤，确保做法图随分包进入真机调试和体验版。
- 其余成品照片和桌景封面由 ImageGen 生成。设计参考图与微信头像保存在仓库中，微信打包时会排除这些目录。
